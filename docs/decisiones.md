# Decisiones

| ID | Estado | Decisión | Fecha |
|---|---|---|---|
| D-001 | ACEPTADA | Repo privado hasta el fallo del GOBTEC (las bases solo exigen publicar el código de la propuesta ganadora en 60 días naturales desde el fallo). LICENSE EUPL-1.2 desde el inicio. Si gana, se hace público. | 2026-10-30 |
| D-002 | ACEPTADA | Bootstrap sin `/spec` (scaffolding reversible). Dominio multi-tenant y reservas: spec primero. | 2026-10-30 |
| D-003 | ACEPTADA | Aislamiento multi-tenant por columna `tenant_id` con **defensa en profundidad: filtro aplicativo obligatorio + Row Level Security de Postgres** (policy + `FORCE ROW LEVEL SECURITY`), de modo que el aislamiento resiste un bug de código aplicativo. Alternativas evaluadas: solo filtro (un bug = fuga), solo RLS (no se prueba la capa aplicativa), esquema por tenant y BD por tenant (coste de migraciones y operación). Coste asumido: GUC de tenant local a la transacción (`set_config(..., true)`), rol de aplicación no privilegiado, dos credenciales (migrador y app), cuidado con el pool. Coste de cambiar después: de columna a esquema/BD es caro (reescribir migraciones y mover datos); quitar RLS es trivial. Spec: `docs/SDD-multi-tenant.md`. | 2026-10-30 |
| D-004 | ACEPTADA | Tenant = concello con `id` uuid surrogate + `slug` único (el header `X-Tenant-Id` lleva el slug) + `codigo_ine` único como atributo, no como clave (las fusiones de concellos cambian el INE). Sin columna `activo`; altas solo por migración. | 2026-10-30 |
| D-005 | ACEPTADA | Resolución del tenant detrás de un puerto de infraestructura (`TenantResolver`). El resolver por header solo existe en dev/test; prod no tiene resolver (fail-closed) hasta la spec de auth. Errores: 400 si falta o es inválido, 404 si el concello es desconocido. Semilla de concellos (A Estrada 36017, Lalín 36024) solo en dev/test, nunca en prod. | 2026-10-30 |
| D-006 | ACEPTADA | Rol `pistaberta_app` creado en V2 de forma idempotente (`DO $$ ... IF NOT EXISTS`), con contraseña por placeholder de Flyway; la app nunca usa owner ni superuser. Todo acceso a datos va dentro de transacción (GUC transaccional); fuera de transacción devuelve 0 filas; async e hilos virtuales fuera de alcance. **Riesgo de implantación:** en Postgres gestionado (RDS, Supabase, hosting municipal) el migrador puede NO tener `CREATEROLE`; entonces ops pre-aprovisiona el rol y la migración solo hace `GRANT`. No se implementa ahora. | 2026-10-30 |
| D-007 | ACEPTADA | Invariante de no-solapamiento de reservas en **dos capas**: dominio (`DisponibilidadePista`, fallo rápido con `SlotNonDisponible`) y BD (`EXCLUDE USING gist` con `btree_gist` sobre `tstzrange(inicio, fin)`). Intervalo semiabierto `[inicio, fin)` (las adyacentes no solapan) y constraint **parcial** `WHERE estado = 'confirmada'` (cancelar libera la franxa). Alternativas evaluadas: solo dominio (no resiste concurrencia), solo BD (error tardío y SQL crudo), bloqueo pesimista / `SERIALIZABLE` (más contención). Las mutaciones se separan por tier (dominio vs BD): quitar la constraint tumba RV2 y RV4 como dos facetas de la misma barrera, y un RV4 verde sin el aserto de `pg_stat_activity` que prueba el bloqueo de la 2ª transacción es verde mudo. Spec: `docs/SDD-reservas.md`. Aceptada por Pe (visto a la spec, PR #5). | 2026-10-30 |
| D-008 | ACEPTADA | La exclusion constraint incluye `tenant_id WITH =` además de `pista_id` (las comprobaciones de exclusión no pasan por RLS y el índice debe empezar por `tenant_id`); FK **compuesta** `(tenant_id, pista_id)` hacia `pista`; mínimo privilegio: la app solo `SELECT` en `pista` y `SELECT, INSERT, UPDATE` (sin `DELETE`) en `reserva`. Aceptada por Pe (visto a la spec, PR #5). | 2026-10-30 |
| D-009 | ACEPTADA | El adaptador traduce `23P01` (`reserva_sen_solape`) a `SlotNonDisponible` y `23503` (`reserva_pista_fk`) a `PistaNonExiste`; nunca SQL crudo en el caso de uso. La transacción se abre con un puerto `Transaccion` en `application` (implementado con `TransactionTemplate` en infraestructura) para que `application` siga sin Spring. Aceptada por Pe (visto a la spec, PR #5). | 2026-10-30 |
